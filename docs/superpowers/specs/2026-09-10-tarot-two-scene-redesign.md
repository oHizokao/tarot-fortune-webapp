### A — เตรียมคำถามและหยิบไพ่

Header เตี้ย: Tarot Daily / เปิดไพ่เอง · ถามไพ่ AI / ประวัติ / เข้าสู่ระบบหรือบัญชี

ตรงกลางเป็นพื้นที่เดียว กว้างไม่เกิน 1120px: หัวข้อสั้น → ช่องคำถาม (เฉพาะ AI) → สำรับหมุนได้ → ปุ่มทำนายกลางจอ + ล้างไพ่รอง

คำถามและสำรับอยู่หน้าเดียวกัน; จอ desktop 1440×900 ควรเห็นช่องคำถาม สำรับ และปุ่มหลักโดยไม่ผ่าน hero/banner ยาว มือถือยอมเลื่อนตามธรรมชาติแต่ห้ามซ้อนบล็อกคำแนะนำจำนวนมาก

สำรับมี 78 ตำแหน่งคงที่เรียงเป็นริบบิ้น/วงรี 3 มิติที่ลากหมุนได้ รู้สึกเห็นทั้งสำรับ มีไพ่ด้านหน้าใหญ่กดง่าย ไม่ใช่ภาพตกแต่ง 7 ใบ หมุนแล้วตำแหน่งไพ่และสถานะต้องตามตัวเดิม ไพ่ด้านหลังไม่รับคลิกทะลุ หมุน/ลากไม่ทำให้หยิบโดยบังเอิญ

### B — ฉากผลการทำนาย

เปลี่ยนเป็นอีกหน้าจอจริงในเชิงการมองเห็น ไม่ใช่ scroll ผ่าน A ลงมา B; ใช้ views ใน HTML เดิมและ hash/history ได้ ไม่จำเป็นต้อง reload

ลำดับ: คำถามของรอบนี้ → ไพ่จริง 1–3 ใบขนาดใหญ่พลิกทีละใบ → ชื่อ/ความหมายสั้น/คำทำนายรายใบ → `คำทำนายโดยรวม` ด้านล่าง → `ถามต่อ · จับไพ่ใหม่` / `ล้างไพ่`

จอใหญ่: ภาพไพ่ 1–3 ใบวางกลางจอเท่ากัน แต่ละใบมีข้อความเรียงลงใต้ภาพ ห้ามแบ่งข้อความภายในไพ่เป็นคอลัมน์แคบ ๆ จนคำไทยตกร่อง สรุปกว้าง 680–760px กลางจอ

มือถือ: เรียงภาพและคำอ่านทีละใบลงแนวตั้งเพื่ออ่านได้เต็มจริง ภาพกว้างประมาณ 200–260px; ไม่บีบ 3 คำทำนายเป็น 3 คอลัมน์ แตะภาพขยายและปิดกลับได้ ตัวอักษรเนื้อหาอย่างน้อย 16px line-height 1.65–1.8

ใช้ภาพจากสำรับเดิมทั้งแผ่น `object-fit: contain; height:auto`; ห้าม crop คำบนไพ่; ข้อความอยู่นอกรูป ไม่มีแถบ/ตัวละครปิดรูป ไม่มีหัวข้อซ้ำเป็นสิบชั้น ไม่มีคำแนะนำถัดไปหรือคำถามชวนทบทวนเพิ่มเอง

คำตอบสั้น ตรงประเด็นคำถามล่าสุด เชื่อมความหมายของไพ่รายใบและสรุป ไม่แทนคำตอบจริงด้วยข้อความตัวอย่าง; คงข้อจำกัดเดิมเรื่องการแยกคำทำนายจากข้อเท็จจริงสำคัญ ไม่ขยายงานเป็นเปลี่ยน model/prompt รอบนี้

### ถามต่อ ประวัติ และสองโหมด

- ถามต่อจาก B กลับ A ช่องเดิมบนสุดว่างพร้อมพิมพ์ เก็บสำรับ/ตำแหน่งที่ใช้/Memory; รอบใหม่หยิบจากใบเหลือ ไม่ส่งคำถามเก่าซ้ำ ไม่ reuse ไพ่รอบเก่า
- ล้างไพ่ = สับสำรับใหม่ 78 ใบและเริ่มบทสนทนาใหม่; ประวัติที่บันทึกอยู่ไม่ถูกลบ
- ล็อกอินใหม่เริ่ม A พร้อมดูดวงใหม่ ประวัติเก่าเปิดได้จากปุ่มประวัติ; ดูย้อนหลังไม่เขียนทับสำรับที่กำลังเล่น
- มีดูประวัติและลบรายรายการ/ทั้งหมดตามขอบเขตเดิม ลบด้วยการยืนยันใน UI; การเปิดหน้า history ไม่เรียก AI ซ้ำ
- Guest: A ไม่มีช่องคำถาม/AI; CTA `เปิดไพ่`; B มีไพ่และชื่อเท่านั้น CTA `จับไพ่ต่อ`; AI: CTA `ทำนาย` และตีความอัตโนมัติหลังเลือกและส่งครั้งเดียว
- เก็บ login/signup, สิทธิ์อนุมัติสมาชิก, `/admin/`, API key และ prompt setting ฝั่ง server; ไม่เอาลิงก์หลังบ้านมาเป็นปุ่มหลักสำหรับลูกค้า
- คง export/Copy ภาพของชุดถ้ามีในของเดิม พร้อมทางดาวน์โหลดเมื่อ clipboard ไม่รองรับ ไม่เพิ่ม sharing service ใหม่

## Art direction และ Motion ที่มีหน้าที่

- พื้น midnight indigo `#0B0920`, foreground `#F5F1FF`, muted `#BDB4D5`, accent lavender `#A78BFA` + warm gold `#E7CC8B`; body สีคอนทราสต์อ่านได้
- ใช้ font ไทยเดิม น้ำหนักปกติ; ตัด panel border ซ้อนและกล่องขั้นตอน/ข้อความอังกฤษซ้ำ ใช้ระยะห่างแทนกรอบ ไพ่อยู่ศูนย์กลาง ตัวละครเล็กเป็นตราผู้ทำนายสูงไม่เกิน 80px หรือไม่ต้องปรากฏในพื้นที่อ่าน
- ดาว/หมอก/วงเวทเคลื่อนช้าต่อเนื่องเมื่อหน้าแสดง ไม่เลื่อนหรือหมุนข้อความ ห้ามกระพริบแรง
- สำรับหมุนเบา ๆ 35–50 วินาทีต่อรอบ; หยุดเฉพาะขณะ hover/focus/ลากเพื่อกดแม่น ไม่ถือเป็นการปิด Motion ทั้งหน้า
- เลือก: ยกและ glow 160–220ms; เปลี่ยนฉาก: fade + translate/scale 300–450ms; ไพ่พลิก 550–700ms stagger 140–180ms
- เมื่อ draw สำเร็จเปลี่ยน B และเปิดไพ่ ระหว่างรอ AI วงเวทหมุนเด่นพร้อม `กำลังอ่านคำทำนาย…` และจำนวน 3/75 ที่คงที่ ไม่มีเปอร์เซ็นต์โหลดปลอม
- AI ตอบแล้วข้อความ fade-in 200–300ms และหยุด loader ทันที ไม่หน่วงคำตอบเพื่อบังคับโชว์ animation
- เปิด Motion เป็นค่าเริ่มต้น ไม่มีปุ่มเปิด/ปิด; เมื่อระบบผู้ใช้ขอ reduced motion ลดการหมุนเป็น glow/fade ที่นุ่มนวล ใช้งานได้ครบ; หน้า background หยุดงานที่กินเครื่อง
- ใช้ DOM/CSS perspective + Web Animations API บน stack เดิมก่อน ไม่ต้องเปลี่ยนเป็น React หรือเพิ่ม Three.js ทั้งโปรเจกต์
