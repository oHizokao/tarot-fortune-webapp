# Tarot Daily Pro Ritual Reader Design

## Goal

ทำให้ Tarot Daily ให้ความรู้สึกเป็นเว็บอ่านไพ่ระดับโปร โดยคงสองโหมดเดิมไว้:

- Guest เปิดไพ่ด้วยตัวเองได้โดยไม่ต้องล็อกอิน
- สมาชิกพิมพ์คำถาม เลือกไพ่ และรับคำทำนายจาก AI ได้

ประสบการณ์หลักต้องอ่านได้ในไม่กี่วินาที:

    พิมพ์คำถาม → เลือกไพ่ → ทำนาย → อ่านคำตอบ

## Design direction

ใช้แนวทาง Pro Ritual Reader ซึ่งหยิบหลักการจาก ref ของ ChatTarot มาใช้เฉพาะด้าน flow:

- compose scene เดียวสำหรับคำถามและสำรับไพ่
- result scene แยกสำหรับอ่านคำตอบ
- ไพ่เป็นวัตถุหลักที่ผู้ใช้สัมผัสและหมุนได้
- คำทำนายสั้น ตรงคำถาม และมีสรุปท้ายหน้า

ไม่คัดลอกโค้ด อาร์ตเวิร์ก หรือ layout เฉพาะของ ref ให้ใช้ witch asset และภาพไพ่ของโปรเจกต์นี้ต่อไป

## User experience

### Guest compose

หัวหน้าเว็บและข้อความสั้น ๆ → สำรับ 78 ใบ → ไพ่ที่เลือก 1–3 ใบ → ปุ่ม เปิดไพ่

Guest ไม่เห็นช่องถาม AI และไม่ถูกบังคับให้ล็อกอิน

### Member compose

หัวหน้าเว็บ → ช่องพิมพ์คำถาม → สำรับ 78 ใบ → ไพ่ที่เลือก 1–3 ใบ → ปุ่ม ทำนาย

ปุ่มทำนายต้อง disabled จนกว่าจะมีคำถามและไพ่ที่เลือกอย่างน้อย 1 ใบ

### Deck state

แยกสถานะอย่างชัดเจน:

- available: ไพ่ปกติ กดเลือกได้
- selected: ไพ่ที่เลือกในรอบปัจจุบัน สีเด่น มี glow
- locked: เมื่อเลือกครบ 3 ใบ ไพ่ที่ยังไม่เลือกจะ dim และกดไม่ได้
- used: ไพ่ที่ถูก commit ในรอบก่อน สีดำ/เทา กดไม่ได้
- pending: ไพ่ของรอบที่กำลังส่งคำขอ มีสถานะกำลังอ่าน

selectedIndexes เป็นไพ่ของรอบปัจจุบันเท่านั้น ส่วน usedIndexes เป็นไพ่ที่ commit แล้วเท่านั้น ห้ามนำสองชุดนี้ไปรวมกันจนทำให้จำนวนผิด

ตัวเลขบนหน้าให้สื่อความหมายเดียวกัน:

    ใช้ไปแล้ว X / 78 · กำลังเลือก Y / 3 · เหลือ Z ใบ

ระหว่างรอ network หรือ AI ต้องคงตัวเลขและไพ่ที่เลือกไว้ให้เห็น หากคำขอล้มเหลวให้ retry รอบเดิมได้โดยไม่ mark ไพ่ซ้ำ

### Result scene

ลำดับเนื้อหา:

1. คำถามที่ใช้เปิดไพ่
2. รูปไพ่ที่เปิดได้แบบเต็มสัดส่วน
3. ฟันธงคำถามนี้
4. อ่านไพ่ทีละใบ
5. สรุปคำทำนาย
6. ปุ่ม ถามต่อ / จับไพ่ต่อ อยู่ด้านบนของ action area

ห้ามมีคำว่า คำแนะนำถัดไป หรือ คำถามชวนทบทวน ในคำตอบ

### Follow-up

ถามต่อจะกลับไป compose scene และ:

- แสดงคำถามเดิมเป็นบริบทเล็ก ๆ
- ล้างช่องคำถามเพื่อให้พิมพ์คำถามใหม่
- คง usedIndexes เดิม
- ให้เลือกไพ่ใหม่จากไพ่ที่ยังไม่ใช้
- ไม่ตอบซ้ำคำถามเดิม

ล้างไพ่เท่านั้นที่สร้างสำรับใหม่ครบ 78 ใบ

## Visual system

- ใช้หนึ่งพื้นผิวต่อหนึ่ง scene ไม่ซ้อนกล่อง panel หลายชั้น
- ใช้ whitespace, divider และ typography แทนกรอบจำนวนมาก
- ให้ deck stage เป็นจุดเด่นที่สุดใน compose
- ให้ card/result typography เป็นจุดเด่นที่สุดใน result
- จำกัด content width ให้คงที่บนจอใหญ่
- ปุ่มหลักหนึ่งปุ่มต่อช่วงการใช้งาน
- สีทองใช้กับคำทำนายและสถานะสำคัญ
- สีเขียวมิ้นต์ใช้กับ selected/success
- สีม่วงและฟ้าใช้กับ ambient magic

## Motion

Motion เปิดเสมอ:

- วงล้อและเส้นวงแหวนหมุนช้า ๆ
- ดาวและแสงเคลื่อนเบา ๆ
- ไพ่ตอบสนองเมื่อ hover/touch
- ไพ่พลิกหรือ reveal แบบ stagger หลังสั่งทำนาย
- ระหว่างรอ AI แสดง ritual ring และข้อความกำลังอ่านคำบนไพ่

ต้องไม่ใช้ motion ที่ทำให้เลือกไพ่โดยไม่ได้ตั้งใจ และต้องมี fallback ที่ลดความถี่/ระยะของ animation สำหรับผู้ใช้ที่ตั้ง reduced motion

## AI answer contract

ผลลัพธ์จาก API ต้องถูกนำเสนอใน schema เดียว:

    {
      verdict: string,
      cards: [{ position, name, meaning, prediction }],
      overall_prediction: string,
      safety_note?: string
    }

verdict ต้องตอบทิศทางของคำถามก่อน แล้วแต่ละใบต้องอธิบายจาก keyword ของไพ่และเชื่อมกับคำถามนั้นโดยตรง overall_prediction ต้องสรุปทิศทางเดียวกับ verdict ห้ามแตกประเด็น

## Responsive and accessibility

- รองรับ 360, 390, 768, 1024 และ 1440px
- ไม่มี horizontal overflow
- ไพ่ผลลัพธ์เห็นเต็มใบด้วย object-fit: contain
- interactive target อย่างน้อย 44px
- keyboard focus และ aria label ครบ
- 78 ใบยังคงเลือกได้บนมือถือโดยใช้ touch drag/scroll
- ไม่โหลดภาพผลลัพธ์ทั้งหมดแบบ eager

## Definition of done

- ผู้ใช้ใหม่เข้าใจ flow หลักโดยไม่ต้องอ่านคู่มือ
- Guest เปิดไพ่ได้จริงโดยไม่ล็อกอิน
- Member ใช้ AI ได้ตามลำดับคำถาม → ไพ่ → ทำนาย
- selected/used/pending ไม่ปะปนกัน
- จำนวน 78 ใบถูกต้องทั้งก่อน ระหว่าง และหลัง request
- ผลลัพธ์อ่านง่าย ไม่เป็นกำแพงข้อความ
- ถามต่อได้ไพ่ใหม่และไม่ซ้ำ
- ประวัติไม่บังการเริ่มดูดวงรอบใหม่
- desktop/mobile ไม่มี layout แตก
- local test, E2E และ production smoke test ผ่าน
