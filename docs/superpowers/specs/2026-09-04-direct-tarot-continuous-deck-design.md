# Direct Tarot Reading and Continuous Deck Design

## Goal

ทำให้ Tarot Daily เป็นระบบเปิดไพ่ที่ตอบคำถามแบบคำทำนายตรงประเด็น และใช้สำรับเดียวต่อเนื่องหลายรอบจนกว่าผู้ใช้จะกดล้างไพ่และสับใหม่

## Problem

ระบบเดิมมีคำสั่งที่ทำให้ AI ระวังจนตอบกำกวม เช่น ห้ามกล่าวว่าสิ่งใดจะเกิดขึ้นแน่นอน และให้แจ้งข้อจำกัดเมื่อคำถามเป็นข้อเท็จจริง จึงตอบเบี่ยงจากเจตนาของการดูดวง เช่น ตอบให้ไปตรวจพยากรณ์อากาศแทนการอ่านไพ่

ระบบเดิมยังจำลองการถามต่อด้วยการสร้าง `reading_sessions` ใหม่แล้วปิดชุดเดิม ทำให้ความหมายของ “สำรับเดียวที่เปิดต่อไปเรื่อย ๆ” ไม่ชัด แม้ฝั่งเบราว์เซอร์จะพยายามเก็บไพ่ที่เปิดแล้วไว้ก็ตาม

## Product rules

### Free manual mode

- ไม่ต้องล็อกอิน
- เลือกไพ่ 1, 2 หรือ 3 ใบ
- เปิดไพ่และอ่านความหมายด้วยตัวเอง
- กดเปิดต่อได้จากไพ่ใบที่เหลือในสำรับเดิม
- ไพ่ต้องไม่ซ้ำจนกว่าจะเปิดครบ 78 ใบ
- กด “ล้างไพ่และสับใหม่” จึงเริ่มสำรับ 78 ใบใหม่

### Member AI mode

- ต้องล็อกอินและได้รับสิทธิ์ AI
- ลำดับบังคับคือ พิมพ์คำถาม → เลือกจำนวนไพ่ → เปิดไพ่ → รับคำฟันธง
- หลังได้คำตอบ กดถามต่อได้ โดยพิมพ์คำถามใหม่และเลือกไพ่ 1, 2 หรือ 3 ใบอีกครั้ง
- การถามต่อใช้สำรับเดิมและตัดไพ่ใบถัดไป ไม่สร้างสำรับใหม่
- คำถามก่อนหน้าใช้เป็นบริบทได้ แต่คำถามล่าสุดและไพ่รอบล่าสุดมีความสำคัญสูงสุด
- คำถามคนละเรื่องต้องใช้ปุ่มล้างไพ่และสับใหม่ เพื่อเริ่ม Memory ใหม่
- รีโหลดหน้าเว็บหรือออกแล้วกลับเข้าใช้งานต้องกู้สำรับ ประวัติ และรอบล่าสุดได้

### Deck invariants

- หนึ่งการสับไพ่มีลำดับไพ่ 78 ใบที่คงที่
- ทุกการเปิดเป็น round ที่มีหมายเลข, คำถาม, ไพ่ และคำตอบของตัวเอง
- การตัดไพ่ต้องทำแบบ atomic และมี idempotency key เพื่อป้องกันการกดซ้ำ/รีทรายแล้วได้ไพ่ซ้ำ
- เมื่อไพ่เหลือน้อยกว่าจำนวนที่เลือก ปุ่มจำนวนที่เกินต้องใช้ไม่ได้
- เมื่อครบ 78 ใบ แสดงเฉพาะการเริ่มการสับใหม่ ไม่พยายามสุ่มต่อ

## Direct answer contract

AI ต้องส่งข้อมูลที่ตรวจรูปแบบได้ โดยมีช่องดังนี้:

- `verdict`: คำฟันธงหนึ่งหรือสองประโยค ตอบคำถามล่าสุดทันที
- `cards`: รายการไพ่ที่เปิดจริงตามจำนวน พร้อม `name`, `meaning` และ `prediction`
- `overall_prediction`: คำทำนายรวมที่เชื่อมคำบนไพ่กับคำถามล่าสุด
- `safety_note`: เว้นว่างสำหรับคำถามทั่วไป และใช้เฉพาะเมื่อเป็นประเด็นเสี่ยงสูง

หน้าจอต้องแสดงตามลำดับ:

1. คำฟันธงจากไพ่
2. ไพ่ที่เปิดได้
3. ความหมายและคำทำนายของไพ่แต่ละใบ
4. คำทำนายโดยรวม

คำตอบทั่วไปห้ามแทรกประโยคเลี่ยง เช่น “ไพ่ไม่สามารถบอกได้”, “ควรไปตรวจสอบข้อมูลจริง”, “คุณเป็นผู้ตัดสินใจเอง” หรือคำแนะนำถัดไปที่ไม่ตอบคำถาม การเตือนเรื่องความบันเทิงให้อยู่ใน footer/ข้อความช่วยเหลือ ส่วนคำถามสุขภาพ กฎหมาย การเงิน ความปลอดภัย และการทำร้ายตัวเองให้ใช้ safety note สั้น ๆ โดยยังตอบเชิงสัญลักษณ์ให้ตรงเรื่องเท่าที่ปลอดภัย

## Data model

สมาชิกใช้ `reading_sessions` เป็น deck session เดียว และมี `reading_rounds` เป็นลูกของ session:

- session เก็บลำดับสำรับ, cursor, จำนวนที่เปิด, สถานะ active/closed และเวลา
- round เก็บเลขรอบ, คำถาม, ไพ่ที่ถูกตัด, JSON คำตอบ, ข้อความคำตอบ และสถานะ drawn/answered/failed
- `reading_messages` ใช้เก็บบทสนทนาเพื่อ Memory ต่อเนื่อง และผูกกับ round ได้เมื่อมีรอบใหม่
- ข้อมูล `reading_sessions` แบบเก่าต้องอ่านได้ต่อเพื่อไม่ทำลายประวัติเดิม

ผู้ใช้ทั่วไปใช้ shape เดียวกันใน localStorage โดยมี `deckOrder`, `cursor`, `rounds` และ `activeQuestion` แทนข้อมูลฝั่งฐานข้อมูล

## UI direction

ใช้รางแนวตั้งเดียวแบบพิธีเปิดไพ่ ไม่ใช้กล่องซ้อนหลายชั้น:

```text
คำถามของคุณ
จำนวนไพ่ 1 / 2 / 3
เปิดไพ่
ไพ่รอบนี้
คำฟันธง
คำทำนายรายใบและโดยรวม
ถามต่อจากเรื่องเดิม
```

ตัวเลือกจำนวนไพ่ต้องใหญ่และกดง่าย, ปุ่มหลักใช้คำว่า “เปิดไพ่”, ไพ่ต้องแสดงครบอัตราส่วนจริง, และ motion เปิดทีละใบต้องทำงานทุกครั้งบน desktop และ mobile

## Acceptance criteria

1. ผู้ใช้ทั่วไปเปิด 3 ใบ แล้วเปิดต่อ 2 ใบ ได้ไพ่ใหม่ 5 ใบและเหลือ 73 ใบ โดยไม่ซ้ำ
2. สมาชิกถามคำถามแรก ได้คำฟันธงและคำทำนายรายใบ
3. สมาชิกถามต่อ เลือกจำนวนไพ่ใหม่ ได้ round ใหม่ในสำรับเดิม ไม่ปิด/สร้างสำรับใหม่
4. Reload และ login ใหม่กู้ round, ไพ่ที่เหลือ, คำถาม และคำตอบได้
5. กดล้างไพ่และสับใหม่ทำให้เหลือ 78 ใบและ Memory ของเรื่องเดิมไม่ถูกนำมาใช้
6. คำตอบที่แสดงมี `คำฟันธง` ที่ตอบคำถามล่าสุด และไม่มี section “คำแนะนำถัดไป” หรือ “คำถามชวนทบทวน”
7. คำตอบคำถามสภาพอากาศในโหมดไพ่ต้องเป็นคำทำนายจากไพ่ ไม่เปลี่ยนไปเป็นคำตอบตรวจพยากรณ์อากาศ
8. Desktop และ mobile ไม่มี horizontal overflow และเห็นไพ่เต็มใบ
