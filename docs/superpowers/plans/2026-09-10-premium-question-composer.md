# Premium Question Composer Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement the tasks below in order when implementation is authorized. Track steps using the checkboxes. Follow the user's latest instructions and use verification proportionate to the change.

**Goal:** ทำให้ช่องพิมพ์คำถามของ Tarot Daily อ่านชัด เห็นทันทีว่าต้องเริ่มตรงไหน และให้บรรยากาศพรีเมียมจากการจัดวาง สี และ motion ที่อ้างอิง CHATAROT.AI

**Architecture:** ปรับหน้า compose ของ `/ai/` บน HTML/CSS/JavaScript เดิม โดยใช้ `#ai-question` และ event handlers เดิมต่อไป จัดช่องพิมพ์กับสำรับให้อยู่ในแนวกลางเดียวกัน และคงหน้า result แยกจาก compose ตามระบบเดิม การแก้หลักอยู่ใน CSS ของคำถามและข้อความที่ `renderQuestionComposer()` / `setReaderMode()` สร้างขึ้น

**Tech Stack:** HTML, CSS, native JavaScript modules, Node test runner, Playwright, Vercel

**Spec:** คำขอล่าสุดของผู้ใช้วันที่ 10 กันยายน 2026, Design brief ในเอกสารนี้ และข้อกำหนดระบบเดิมใน `../specs/2026-09-10-tarot-pro-ritual-design.md`

**Status:** แผนเสนอสำหรับการปรับ UI — ยังไม่ได้แก้ไฟล์แอปหรือ deploy ตามแผนนี้

## Global Constraints

- ผู้ไม่ล็อกอินยังเปิดไพ่ธรรมดาได้; สมาชิกที่มีสิทธิ์ AI จึงเห็นช่องพิมพ์คำถาม
- สมาชิกใช้ลำดับเดิม: พิมพ์คำถาม → เลือกไพ่ 1–3 ใบ → ทำนาย → หน้าแสดงผล
- คำถามและการเลือกไพ่อยู่หน้าเดียวกัน; ปุ่มทำนายหลักมีจุดเดียวใต้สำรับ
- ถามต่อกลับมาช่องพิมพ์ด้านบน พร้อมเลือกไพ่ใหม่จากสำรับเดิมและใช้ memory เดิม
- ประวัติอยู่ใต้พื้นที่อ่านไพ่ ก่อน footer ตามการแก้ v42
- คงระบบ 78 ใบ, selected / pending / used, การนับจำนวน, retry และการล้างสำรับเดิม
- คงชื่อ `ทำนาย` และ `ล้างไพ่`; ไม่เพิ่มขั้นตอนยืนยันหรือหน้าคั่น
- ใช้รูปไพ่และอัตลักษณ์ Tarot Daily เดิม; ไม่ต้องเพิ่ม React, UI framework หรือ WebGL สำหรับงานนี้
- คง motion เป็นค่าเริ่มต้น พร้อม reduced-motion ที่เหมาะสม; ช่องพิมพ์และข้อความต้องอยู่นิ่ง
- ไม่เปลี่ยน prompt ของ AI, model, API key, auth, database หรือระบบสิทธิ์ในงานตกแต่งนี้

## Design brief

### 1. จุดเริ่มใช้งานที่ชัดเจน

- หัวข้อกลางหน้า: `วันนี้อยากถามไพ่เรื่องอะไร?`
- ลดคำอธิบายยาวเหลือหนึ่งบรรทัด: `พิมพ์คำถาม แล้วเลือกไพ่ได้สูงสุด 3 ใบ`
- ช่องพิมพ์มี label จริง `คำถามของคุณ` และ placeholder สั้น `เช่น ความรักช่วงนี้จะเป็นอย่างไร?`
- ตำแหน่งช่องพิมพ์อยู่ต่อจากหัวข้อทันที; ย้ายชื่อบัญชี/ออกจากระบบให้อยู่แถบหัวเว็บ
- ลดเลขขั้นตอนและข้อความภาษาอังกฤษตกแต่งที่ซ้ำกัน เพื่อให้สายตาไปที่คำถามและไพ่
- ใช้กรอบเฉพาะพื้นที่รับข้อความที่จำเป็นต่อการรู้ว่าพิมพ์ได้; รอบ section ใช้พื้นที่ว่างแทนกล่องซ้อน

### 2. สัดส่วนและสีที่กำหนดไว้

| รายการ | Desktop | Mobile |
| --- | --- | --- |
| แนวเนื้อหาหลัก | กว้างสูงสุด 1000px อยู่กึ่งกลาง | ขอบซ้ายขวา 16–20px |
| ช่องพิมพ์ | กว้างสูงสุด 760px อยู่กึ่งกลาง | กว้างเต็มพื้นที่เนื้อหา |
| ความสูงช่องพิมพ์เริ่มต้น | 148–168px | 136–160px |
| ตัวอักษรที่พิมพ์ / placeholder | 18px, line-height 1.75 | อย่างน้อย 16px, line-height 1.75 |
| Label / hint | 15px / 14px | 15px / 14px |
| Padding ช่องพิมพ์ | 22–24px | 16–18px |
| มุมและขอบ | radius 16px, ขอบ 1px มองเห็นได้ | เหมือน desktop |
| ปุ่มหลัก | สูงอย่างน้อย 52px | สูงอย่างน้อย 52px กว้างเต็มแถว |

สีตั้งต้นที่ต้องตรวจจากหน้าที่ render จริง:

```css
/* วางตัวแปรใน scope ของ #ai-reader-app เดิม */
--composer-surface: #171320;
--composer-text: #f5f0e8;
--composer-placeholder: #bab2c8;
--composer-border: #81728c;
--composer-accent: #d8bf8c;
```

พื้นหน้าเป็นดำอมม่วง ลดแสงม่วง/ฟ้าที่ฟุ้งผ่านจุดอ่าน แชมเปญใช้กับ focus, รายละเอียดเล็ก ๆ และปุ่มหลัก ตัวอักษรและ placeholder มี contrast เป้าหมายอย่างน้อย 4.5:1 บนพื้นจริง

รูปแบบ CSS ที่ต้องได้ใน selector ของ textarea ที่มีผลจริง:

```css
width: min(100%, 760px);
min-height: 148px;
margin: 12px auto 0;
padding: 22px 24px;
border: 1px solid var(--composer-border);
border-radius: 16px;
background: var(--composer-surface);
color: var(--composer-text);
font-size: 18px;
line-height: 1.75;
resize: vertical;
caret-color: var(--composer-accent);
transition: border-color 180ms ease, box-shadow 180ms ease;
```

Placeholder ใช้ `color: var(--composer-placeholder); opacity: 1` และ font เดียวกับข้อความที่พิมพ์ Focus ใช้ขอบทองและ halo บาง ๆ โดยไม่เปลี่ยนความหนาขอบ ไม่ขยับ layout และไม่ใช้ animation กับ textarea

### 3. การไหลของหน้า

```text
หัวเว็บ: Tarot Daily                         บัญชี

             วันนี้อยากถามไพ่เรื่องอะไร?
           พิมพ์คำถาม แล้วเลือกไพ่ได้สูงสุด 3 ใบ

                   คำถามของคุณ
          ┌───────────────────────────────┐
          │ เช่น ความรักช่วงนี้จะเป็นอย่างไร? │
          │                               │
          └───────────────────────────────┘

                 เลือกไพ่ 1–3 ใบ
              [ สำรับไพ่ที่เลือกได้ ]
              สถานะสำรับและไพ่ที่เลือก

                    [ ทำนาย ]
                    ล้างไพ่

                 ประวัติการดูดวง
```

บน desktop ให้หัวข้อและช่องพิมพ์ครบอยู่ในส่วนแรกของหน้าจอ และเริ่มเห็นบริเวณสำรับโดยไม่ต้องผ่านข้อความสถานะหลายชุด เป้าหมายที่ 1440×900: ขอบบนสำรับอยู่ไม่เกินประมาณ 540px เมื่อแสดงช่องคำถามว่าง

เมื่อถามต่อใช้หัวข้อ `อยากถามอะไรต่อ?` และ hint เดียว `เลือกไพ่ใหม่ได้เลย ระบบยังจำเรื่องที่คุยกันไว้` ช่องพิมพ์อยู่ตำแหน่งเดิมและรับ focus ตาม `continueReading()` เดิม

### 4. Motion และมือถือ

- รักษา motion สำรับและวงแหวนเดิม ให้ดาว/แสงตกแต่งอยู่ตามขอบฉากด้วยความเข้มต่ำ
- พื้นช่องพิมพ์ทึบพอที่ภาพเคลื่อนไหวด้านหลังจะไม่เปลี่ยนความชัดของตัวอักษร
- เมื่อ focus ช่องพิมพ์ ใช้ `:focus-within` ลดความเข้มของเอฟเฟกต์ตกแต่งรอบ composer
- transition ปุ่ม/focus ประมาณ 180–240ms; ไม่มีการกระพริบแสงหรือหมุนข้อความ
- ตรวจมือถือ 360, 390 และ 430px: ช่องพิมพ์ไม่มีส่วนล้น, label คงมองเห็น, ปุ่มไม่บังข้อความ
- ตรวจ keyboard จริงบนมือถือก่อนรับรองเรื่องการบังช่องพิมพ์; viewport emulation อย่างเดียวไม่ยืนยันพฤติกรรม keyboard ของอุปกรณ์จริง
